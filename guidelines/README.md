# 规范文档版式

版式层 1.0，2026-11-07。用于在 Figma 里制作规范页、图解规范、验收板和方案对比板。它和[配图层](../illustrations/README.md)共用同一套视觉基础（浅灰衬底、细线、浮起卡片、少量字号），区别在于配图层规定单张 640×360 的说明图，本层规定整页文档怎么排。产品界面和车机控件仍按 `SPEC.md`，本层的数值不进入产品。

写下来的原因：版式此前只存在于制作者的判断里，换一个 Agent 拿到同样的 SPEC，排出的页面会不同。本文件、`layout.json`、Figma 中的 `Doc/*` 组件和 `lint-figma.js` 一起，把这种判断变成可调用、可检查的规则。

## 从哪里开始

1. 读本文件和 [`layout.json`](layout.json)。
2. 在 Figma 文件 lib test 的 Components 页找到 `Doc blocks 1.0`（579:11775），只用其中的 `Doc/*` 组件和 `Doc/*` 文字样式组装页面，不自己画容器。
3. 按下方「页面结构」的顺序填入内容。
4. 用 Figma MCP 的 `use_figma` 运行 [`lint-figma.js`](lint-figma.js)，把 `ROOT_ID` 换成你的页面节点，问题清零后再截图核对。

参考成品：HMI 图标规范试验 567:3423，一块画布，用变量切换中英文。它是按本层排出的实例，内容以图标规范本身为准。

## 页面网格

| 项 | 值 |
| --- | --- |
| 画板 | 宽 1440，内边距 64，内容宽 1312，高度随内容 |
| 节 | 纵向排列，节与节间距 64；节标题到内容 20 |
| 卡片 | 两列宽 644 或四列宽 310，列间距与行间距 24 |
| 卡片内部 | 内边距 24，元素间距 12，圆角 16，corner smoothing 0.6 |
| 样本板 | 实际尺寸放在 80 × 80、圆角 16 的 `bg/face` 上，说明文字在下方，间距 8 |
| 测量板 | 48 槽位放大 4 倍：232 × 232，内边距 20，槽位用 1 px 虚线 3/3 |
| 表格行 | 三列 220 / 560 / 480，列间距 24，上下内边距 12，只有底部 1 px 细线 |
| 编号列表 | 编号 24、陈述 440、证据 600，列间距 24 |

## 字号

只用 5 档，全部建成 Figma 文字样式 `Doc/*`。英文用 Inter，中文用 Noto Sans SC，字号与行高相同（中文可替换为 PingFang SC 或 HarmonyOS Sans SC，同一文档只用一种）。字体由语言变量切换，见下节。

| 样式 | 规格 | 用途 |
| --- | --- | --- |
| `Doc/index` | Medium 10/14，大写，字距 6%（中文 2%） | 节编号与节名、卡片眉题、样本说明、表头、范围行 |
| `Doc/label` | Medium 13/18 | 卡片标题、表格首列、列表陈述 |
| `Doc/body` | Regular 11/17 | 正文、原因、证据 |
| `Doc/title` | Medium 24/32 | 每页唯一的页面标题 |
| `Doc/stat` | Medium 28/32 | 统计数值 |

与配图层 13/18、11/15、10/12 同源；正文行高放宽到 17、编号行高放宽到 14，是为了容纳中文段落。

## 颜色

全部绑定 Figma 变量 `HMI / v0.1`，画板设为 Light 模式，不写死色值。

| 角色 | 变量 |
| --- | --- |
| 画板衬底 | `bg/canvas` |
| 卡片、测量板 | `bg/raised`，描边 `line/face` 1 px |
| 样本底、反例底 | `bg/face` |
| 槽位虚线 | `line/control` |
| 文字 | 标题与陈述 `text/1`，正文 `text/2`，编号与说明 `text/3` |
| 图标 | `icon/1` |
| 测量线和测量数值 | `accent`，只用于测量 |
| 通过 / 不通过 | `status/success` / `danger`，只用于检查结果 |

## 中英文切换

一份文档只做一块画布。变量集 `Doc / Language` 有 EN 与中文两个模式：每段文字绑定一个字符串变量（`<文档>/t001` 起），字体绑定 `doc/font`（Inter / Noto Sans SC），编号标签的字距绑定 `doc/index-tracking`（0.6 / 0.2 px）。切换语言时选中画板，在右侧把 `Doc / Language` 改为 EN 或中文。新增文字必须同时写两种语言并绑定变量，不直接输入文字。

## 页面结构

规范页按这个顺序排，没有内容的节省略，不新增装饰性的节。

| 节 | 放什么 |
| --- | --- |
| 00 | 页面标题（`Doc/title`）和不超过两行的说明：范围、状态、哪些没有改动 |
| 01 | 资产：当前成品的实际尺寸样本 |
| 02 | 几何：4 倍测量板，标出净距、轴线和有意的例外 |
| 03 | 规则：每张卡片 = 眉题（规则编号与检查编号）+ 一句规则 + 一句原因 + 正反例 + 范围 |
| 04 | 规则归属：每条规则由哪一层负责，能拦住哪个已发生的问题 |
| 05 | 停止做的事：陈述 + 带数值的证据 |
| 06 | 待办：上线前还要验证的事项 |

## 写作与版式规则

- 文字之间不用「·」（与 SPEC 第 11 节一致）。节编号与节名之间空两格，例如 `01  图标集`；其余改用逗号、冒号、括号或换行。
- 每条规则后跟一句原因，原因写已经发生过的具体问题。
- 结论写测量值（`净距 3.0`），不写「已检查」「通过」这类不带数值的结论。
- 正例只放当前成品；旧版本只作为反例出现，不单独成栏。
- 一份文档一个主题：浅色。深色核对写进验收记录，不在页面里复制一份深色版本。
- 中英文共用一块画布，用 `Doc / Language` 切换，不复制画布。
- 标注写规则要求的整数下限（例如 `4`、`≥ 4`），实测小数写进检查记录；比例写分数（`× 7/8`），不写 0.875。必须为整数的是槽位、轴线、切口、线宽和位置。
- 不加阴影、渐变、装饰性图形、整页标题之外的标题行或重复说明。删掉任何不承载规则、测量或判断的元素。
- 同类信息用同一个组件；需要新版块时先在 `Doc blocks` 增加组件，并在本文件登记，再使用。

## 检查

`lint-figma.js` 是只读脚本，用 `use_figma` 在目标页面上运行，返回问题列表：

| 检查 | 不合格条件 |
| --- | --- |
| 中点 | 任何文字包含「·」 |
| 字号 | 字号或行高不在 5 档之内 |
| 颜色 | 填充或描边没有绑定变量（图标内部除外） |
| 效果 | 出现阴影或模糊 |
| 主题 | 页面内部出现单独设成 Dark 的节点 |
| 语言 | 文字没有绑定 `Doc / Language` 变量（需要在脚本中开启 `REQUIRE_LANGUAGE`） |
| 圆角 | 圆角不在 0、12、16 之内 |
| 间距 | 自动布局间距不在 `layout.json` 的允许值之内 |

脚本通过只说明版式参数合格，内容是否准确、版面是否清楚仍需截图目检。

## 验证边界

本层根据 2026-11-07 的 HMI 图标规范试验画布整理，组件和样式已在 Figma 中建立。尚未用 Codex 或其他 Agent 独立复现过一页；第一次复现时，用同一份简报分别在「只给截图」和「本层 + 组件 + 检查」两种条件下排版，记录检查结果与需要修改的位置。

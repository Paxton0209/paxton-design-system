# 配图积木与组合参考

配图层 1.0，2026-11-05。作者明确喜欢这批图的感觉，并将其定义为可以继续调用、组合和扩展的视觉积木。现有图提供基础参考，后续配图根据要表达的内容和关系重新组织，数量和版式均可扩展。产品控件仍按根目录 `SPEC.md`，本层用于文章、作品集和解释性示意图。

## 从哪里开始

先看 [16 张参考图](CATALOG.md)，选择最接近当前内容关系的样例，再读下方的组合方式。要使用现有成品，从 `references/` 取 PNG；要重组或制作新图，从 `source/figures.json` 的可编辑 HTML 与 `source/base.css`、`source/v5.css` 的样式开始。`catalog.json` 记录每张图的 ID、关系类型、尺寸、SHA-256 和来源状态，方便 AI 检索和程序调用。

**调用顺序。** 先说清图要帮助读者理解的关系，选必要的视觉元素，安排阅读顺序，再应用材质、字号与对齐。可以改变元素数量、容器排列、分支、顺序和组合；每个元素都应服务于理解，删除没有任务价值的标签、卡片和装饰。根据新内容创建新图时使用新 ID，保留原参考文件和已确认成品。

## 保留的视觉基础

这批图以低饱和中性灰、清晰的表面层级和留白组织信息。浅色衬底为 `#F3F3F3`；面、浮起和占位块区分角色。重点集中在一组元素，其余内容通过明度与层级退后。细线用于结构和连接，虚线用于可选项、边界或时间关系；箭头必须对应有意义的顺序与方向。

配图沿用历史 v5 的 13/18、11/15、10/12 字号，6、10、16 圆角阶梯和 `superellipse(1.6)`。这些是 640 CSS px 配图坐标中的参考值；真实产品和车机控件按 `SPEC.md` 的各自尺度。颜色、材质等细节见 `source/v5.css`，新图优先使用已有 `--fig-*`、`--t-*` 和 `--r-*` 变量。配图 CSS 使用 `.vfig` 作用域，加载时先 `base.css` 后 `v5.css`，避免历史配图变量影响产品控件。

整图按实际内容包围盒组织留白和视觉中心，导出目标为 640×360 CSS px、2x PNG（1280×720）。图内去掉整体标题和冗余说明行，保留理解所需的步骤文字、对象标注和分组标签。图名、文件路径、版本和制作过程留在文档中；标题或图注由使用页面按需要承载。

## 可以拿来组合的元素

以下元素来自当前源文件，按内容需要选用。这个表是起点，新增关系可以组合或扩展元素，并在交付时记录新的用法。

| 元素 | 源文件中的入口 | 解决什么问题 |
| --- | --- | --- |
| 衬底与容器 | `.f-plate`、`.s-stage` | 确定说明范围，组织信息分组 |
| 面与重点 | `.s-lift`、`.s-rest`、`.f-emph` | 表达主次和当前关注对象 |
| 截图或内容占位 | `.f-hero`、`.f-hero__slot`、`.s-bar` | 保留真实内容的位置，减少无关细节 |
| 步骤与方向 | `.f-steps`、`.f-pill`、`.f-arrow` | 表达有顺序的动作或处理过程 |
| 标签与能力 | `.s-tag`、`.s-chip`、`.s-ico` | 命名对象、能力或关键时刻 |
| 连接与边界 | `.s-line`、`.s-node`、`.s-slot`、`.s-vline` | 表达关系、可选项、边界或时间点 |
| 列表与重复项 | `.s-row`、`.f-cols`、`.f-panels` | 组织同类对象和并列比较 |

## 根据内容关系组合

| 内容关系 | 可以参考 | 可以调整的部分 |
| --- | --- | --- |
| 整体与组成 | 原子卡 `anatomy` | 容器中的分区、对象标注与必要说明 |
| 请求到处理结果 | 场景验证 `poc`、反问 `precision` | 截图位、步骤、判断点与能力行 |
| 条件决定去向 | 需求决定框架 `need` | 分支数量、条件与目标容器 |
| 固定边界中的变化 | 框内增长 `production`、只有内容会变 `grow` | 对比对象和内容区占比 |
| 累积或分布 | 热力格 `heat`、可达范围 `reach`、按格子计算 `cells` | 行列、密度、标注与选中位置 |
| 顺序和延续 | 级别卡 `voice`、生命周期 `life` | 阶段数量、时间段和延续关系 |
| 输入汇聚和反馈 | 线索汇聚 `signals`、飞轮 `flywheel` | 输入来源、合流点和回环路径 |
| 场景与观察位置 | D 挡 `drive`、R 挡 `reverse` | 以真实机位和场景依据组织视线与位置 |

新图可以同时使用多种关系，但应保留清晰的主关系。内容过多时拆图，避免为了使用现成积木增加信息。ADAS 的真实机位、车型和场景数据需要另有来源，当前 PNG 只提供已有的场景表达参考。

## 已确认成品与局部修正

已确认的成品使用时保留其结构；作者明确指出问题时只修对应部分。“场景验证”中 `Read the request`、箭头和 `Define the need` 作为一组，相对截图容器水平居中，保留内部顺序与间距。实现位于 `source/base.css` 的 `.vfig #poc .f-steps`。这条规则适用于此图和采用相同居中构图的新图；其他流程布局根据自身关系对齐。

已有“反问”样例中，对象下方的标签跟随对象中线对齐；文字列的标签保持列左缘并核对垂直中线。验收时读取真实坐标并查看导出整图，避免仅凭 CSS 属性推断可见结果。

## 生成与调用

从仓库根目录执行，生成可打开的浅深 HTML；`IDS` 可指定 `catalog.json` 中有可编辑来源的 ID：

```sh
IDS=poc node illustrations/source/build.cjs
npm ci --prefix checks
npx --prefix checks playwright install chromium
node illustrations/source/render.cjs --ids=poc --theme=light
node illustrations/check-assets.mjs
```

HTML 写入 `source/light.html` 与 `source/dark.html`，PNG 和度量写入 `source/renders/`，这些生成文件不提交。查看其他图可使用 `--ids=anatomy,flywheel`；新图先在 `figures.json` 增加独立 ID，再以同一方式生成。导出文件经确认后加入参考目录，并更新 `catalog.json` 的实际尺寸、来源和哈希。调用方可以直接读取 JSON 中的 HTML 字符串，在 `.vfig` 容器中加载；脱离生成器时仍需自行处理画布、去标题和内容布局。
